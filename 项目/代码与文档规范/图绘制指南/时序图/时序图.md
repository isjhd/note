# 时序图

**核心价值**：从代码视角讲清「一个请求进来，各层之间是怎么调用的」，直接对应代码结构，新人改功能、排 bug 能快速定位到对应层级和类。

流程图讲「做什么」，时序图讲「谁按什么顺序做」，是衔接业务设计和代码实现的关键。



## 一、核心元素

1. **参与者(Actor)**： Java 类实例、微服务、中间件或外部系统(如前端、MySQL、Redis)。

2. **生命线(Lifeline)**：代表对象的生命周期。

3. **激活框（Activation）**：生命线上的矩形块，代表对象正在执行方法的时间段，对应方法的调用栈周期。

4. 消息（Message）：对象之间的交互

   - 同步消息：实线箭头，对应 Java 普通方法调用，调用方阻塞等待返回，例如 Service 调用 Mapper 方法。
   - 异步消息：虚线箭头，方法执行完成后的返回结果。
   - 返回消息：虚线箭头，对应`@Async`异步方法、MQ 消息投递等，调用方不等待返回。

5. **组合片段**：表示条件、循环等逻辑

   - `alt`：对应 `if-else` 条件分支

   - `loop`：对应 `for/while` 循环

   - `opt`：对应单分支 `if`（可选逻辑）

   - `par`：对应多线程并发执行

## 二、时序图基础结构

### 1. 最小化示例

```mermaid
sequenceDiagram
    Alice->>John: 你好，John！
    John-->>Alice: 你好，Alice！
```

```
sequenceDiagram
    Alice->>John: 你好，John！
    John-->>Alice: 你好，Alice！
```

**语法解析：**

- `sequenceDiagram`：声明时序图开始
- `participant`：可选，显式定义参与者（会自动按出现顺序创建）
- `->>`：实线箭头，表示同步消息
- `-->>`：虚线箭头，表示异步消息

## 三、消息类型详解

### 1. 六种基本消息箭头

```mermaid
sequenceDiagram
    participant A as 客户端
    participant B as 服务端
    
    Note over A,B: 消息类型演示
    
    A->>B: 同步消息 (实线箭头)
    A-->>B: 异步消息 (虚线箭头)
    B->>+A: 激活开始
    A-->>-B: 激活结束
    A-xB: 失败消息 (带X箭头)
    A--)B: 虚线无箭头

```

```
sequenceDiagram
    participant A as 客户端

    A->>B: 同步消息 (实线箭头)
    A-->>B: 异步消息 (虚线箭头)
    B->>+A: 激活开始
    A-->>-B: 激活结束
    A-xB: 失败消息 (带X箭头)
    A--)B: 虚线无箭头

```

**语法对照表：**

| 语法    | 显示效果      | 含义          |
| :------ | :------------ | :------------ |
| `->>`   | 实线箭头      | 同步调用/消息 |
| `-->>`  | 虚线箭头      | 异步消息      |
| `->>+`  | 实线箭头+激活 | 开始激活      |
| `-->>-` | 虚线箭头+结束 | 结束激活      |
| `-x`    | 带X箭头       | 失败/取消     |
| `--)`   | 虚线无箭头    | 返回/响应     |

## 四、控制流程结构

### 1. 条件分支 (alt/else)

```mermaid
sequenceDiagram
    participant U as 用户
    participant S as 系统
    
    U->>S: 登录请求(用户名,密码)
    
    alt 验证成功
        S-->>U: 返回token
        U->>S: 获取用户信息
        S-->>U: 用户数据
    else 验证失败
        S-->>U: 错误：密码错误
    else 用户不存在
        S-->>U: 错误：用户未注册
    end

```
