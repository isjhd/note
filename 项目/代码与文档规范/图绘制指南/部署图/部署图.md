# 部署图

**核心价值**：解决「项目怎么跑起来、部署到哪了」的问题，让新人快速搭建环境、定位线上问题。

单体项目可以简化，分布式 / 微服务项目建议补充。





## 一、什么是部署图？

部署图描述的是系统运行时的结构，展示了系统的硬件配置、硬件部署，以及其软件如何部署到网络结构中（属于静态视图）。

一个系统模型只有一个部署图，它通常用来帮助理解分布式系统。







## 二、部署图的组成

### 1. 节点（Node）

表示计算资源，分为两类：

- **设备节点**：物理 / 虚拟硬件，如云服务器 ECS、物理机、用户终端、负载均衡硬件。
- **执行环境节点**：运行软件的环境，如 JVM、Tomcat 容器、Docker 容器、K8s Pod、MySQL 实例。



### 2. 制品（Artifact）

Java 项目的实际部署产物，是可部署的物理文件：

- 应用包：JAR 包（Spring Boot）、WAR 包（传统 Java Web）
- 配置文件：`application.yml`、`nginx.conf`、SQL 脚本
- 静态资源：前端 HTML/CSS/JS 文件

核心特征：是软件的「物理实体」，可被部署到节点上运行。



### 3. 组件（Component）

逻辑功能单元，如用户服务、订单服务、权限认证模块，通常由一个或多个制品实现。



### 4. 核心关系

- **部署关系**：虚线箭头 + `<<deploy>>`，表示制品部署到节点上
- **通信路径**：实线连接节点，标注通信协议（HTTP、JDBC、Redis 协议等）
- **展现关系**：虚线 + `<<manifest>>`，表示逻辑组件由物理制品实现







## 三、分步绘制流程

### 1. 明确目标与抽象层级

先确定看图对象和使用场景，控制细节粒度：

- 高层概览（面向甲方 / 产品）：仅保留客户端、应用、数据库 3-5 个核心节点
- 运维交付图（面向运维）：补充防火墙、负载均衡、集群节点、网段划分
- 开发架构图（面向技术团队）：细化微服务、注册中心、配置中心、消息队列等中间件



### 2. 梳理节点清单

典型 Java 项目的节点分层（从上到下）：

- 接入层：用户终端、CDN、负载均衡器（Nginx/F5）
- 应用层：应用服务器、容器集群、微服务实例
- 中间件层：缓存、消息队列、注册配置中心
- 数据层：数据库、对象存储
- 外部依赖：第三方支付、短信网关等



### 3. 映射制品到节点

将 Java 项目的部署产物对应到具体节点，例如：

- `user-service.jar` 部署到应用服务器节点
- MySQL 数据库实例运行在数据库服务器
- 前端静态资源部署在 Nginx 服务器



### 4. 标注通信与协议

用实线连接存在交互的节点，线上标注协议、端口、通信方式，例如：

- 客户端 → Nginx：HTTPS / 443 端口
- 应用 → 数据库：JDBC / 3306 端口
- 微服务间调用：gRPC / HTTP REST



### 5. 补充细节并校验

补充版本号、集群数量、环境标识（生产 / 测试）、网段信息，最终检查：是否所有核心组件都有对应部署节点、通信链路是否完整、是否符合真实部署逻辑。
